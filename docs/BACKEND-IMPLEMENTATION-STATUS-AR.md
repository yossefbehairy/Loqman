# حالة تنفيذ Backend

هذا الملف يصف التنفيذ الحالي، ولا يعتبر خطة البناء مكتملة.

## الموجود

- اكتشاف OpenCode وCodex وClaude Code وAntigravity وفحص الحالة المتاحة دون استدعاء موديل. `GET /api/engines/capabilities` يعرض الحدود.
- `GET /api/engines/{id}/setup` يرجع أمر تسجيل الدخول الرسمي لتشغيله في terminal المستخدم، و`POST /api/engines/{id}/check` يفحص البرنامج والاتصال دون استدعاء موديل؛ نجاح الفحص لا يؤكد حصة الاشتراك أو تشغيل كل موديلات الحساب.
- تنفيذ turn محفوظ عبر `POST /api/conversations/{id}/turns` لمحركات OpenCode وCodex وClaude Code وAntigravity ACP؛ حالة التشغيل وإلغاؤه وأحداثه المحفوظة عبر `/api/conversation-runs/{id}`. يدعم `request_key` لمنع تكرار الطلب و`variant` حيث يدعمه المحرك.
- استدعاءات planner وsynthesis وكل محاولة worker، بما فيها التفويض الصريح لموظف واحد، تُسجل كـruns مستقلة مرتبطة بالمهمة أو المرحلة، مع أحداث وحساب استخدام مرتبطين بالـrun؛ `GET /api/missions/{id}/runs` يعرضها. يتم التحقق من خطة planner قبل نجاح run، والإلغاء يمنع اعتماد ناتج متأخر ويوقف محاولة المحرك بأفضل جهد.
- محرك `mock` متاح لهذا المسار فقط عند ضبط `RUNTIME_MODE=mock` صراحة، ونتائجه محاكاة للعرض والاختبارات.
- حفظ المحادثات والرسائل ونسخة من الـskills المختارة؛ استيراد تاريخ CEO القديم خطوة اختيارية عبر `POST /api/conversations/import/ceo`.
- تسجيل workspace وملفات artifacts للقراءة؛ يمكن إرفاق حتى 3 ملفات نصية يختارها المستخدم ضمن محتوى turn. تسجيل مصادر skills وقراءتها واختيارها للـrun.
- نسخ SQLite احتياطي قبل تحديث schema، وتصدير backup، وأداة استعادة منفصلة تتطلب إيقاف التطبيق. التفاصيل في `BACKUP-RESTORE.md`.
- رمز محلي عشوائي يحمي واجهات `/api/` عندما يشغّل Electron الـbackend. التشغيل المستقل يحتاج `AGENTOS_LOCAL_TOKEN`، أو `AGENTOS_INSECURE_DEV=1` صراحة للتطوير المحلي غير الموثّق.
- تخزين حالات موافقات مرتبطة بالـrun. لا يوجد adapter يطلب أو يفرض هذه الموافقات حاليًا؛ لا تُعتبر حماية لأدوات المحركات.
- يمكن إنشاء مسودة من رد run ناجح، ومراجعتها وقبولها أو رفضها بناءً على hash المحتوى، ثم تنزيل النص المقبول. لا تُكتب المسودة تلقائيًا داخل workspace.
- ملفات الموظفين تقبل محركًا مفضّلًا لمهام mission workers والتفويض الصريح من OpenCode وClaude Code وCodex وAntigravity. يتحقق `POST /api/missions` من كتالوج runtime الافتراضي، ويتحقق `/delegate` من كتالوج محرك الموظف قبل إنشاء السجلات؛ OpenCode يظل free-only، وموديلات الاشتراك تظهر كـunverified حيث لا يستطيع CLI إثبات الفوترة.

## حدود لازمة قبل اعتبار الخطة مكتملة

- الواجهة القديمة ما زالت تستخدم مساراتها الحالية؛ لم تُربط بعد بكل واجهات المحادثات والمحركات الجديدة.
- Antigravity يعمل عبر `agy acp --stdio` ضمن conversation runs وmission workers. يشترط adapter وضع `plan` والموديل المطلوب، ويرفض كل طلب صلاحية من الوكيل؛ هذا لا يثبت عزل workspace أو أن CLI لا يستطيع التصرف بطرق أخرى. `variant` غير مدعوم في هذا الـadapter، ولا توجد موافقات أدوات تفاعلية.
- ربط workspace بالمحادثة يسمح للـbackend بقراءة ملفات نصية يختارها المستخدم وإرسال نسخ محدودة للموديل؛ لا يقيّد وصول CLI نفسه. لا يُعلن عزل workspace حتى يطبقه المحرك ويمكن اختباره.
- Claude وCodex يستخدمان تشغيلًا مؤقتًا بلا استكمال جلسة أو بث نص تدريجي. أحداث الـrun تبث الحالات، لا توكنات الرد.
- المسارات القديمة `/api/chat` و`/api/ceo/ask` ما زالت تفرض قائمة OpenCode المجانية؛ استخدم conversation runs أو mission routes للمحركات/الحسابات الأخرى. لا يوجد بعد اختيار موحد للمزوّد في كل واجهات التطبيق، وواجهة React لم تُربط بمسارات conversation runs.
- OpenCode يمرر محتوى الطلب عبر command line لأن واجهة CLI الحالية لا توفر ملفًا أو stdin للبيانات؛ قد يراه مستخدم محلي آخر بصلاحيات مناسبة. الإلغاء يوقف عملية CLI ويرسل interrupt للجلسة، لكن توقف التوليد البعيد غير مؤكد.
- مسارات missions ما زالت تستخدم orchestration القديمة لترتيب المراحل؛ التخطيط والتجميع وworker والتفويض الصريح محفوظة كـruns. التحية لا تزال استدعاءً مباشرًا، وworkflows على نظام التنفيذ القديم رغم تحسين CAS والإلغاء؛ نقلها الكامل وبث أحداثها القابل للاسترجاع ما زالا مطلوبين.
- استيراد بيانات localStorage، واختبار استعادة كاملة لبيانات مستخدم حقيقية على نسخة آمنة، وحزمة Windows حديثة، واختبار جهاز نظيف ما زالت مطلوبة.

تجارب المحركات الحقيقية استخدمت رسالة قصيرة فقط؛ اختبارات العقود تستخدم CLI وهميًا. لا تعني تجربة الرد القصير اختبار كل موديل أو تسجيل دخول أو صلاحية أداة.
