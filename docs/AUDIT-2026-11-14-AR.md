## أولًا: مشاكل جزء AI providers

### أخطاء فعلية

1. **«Ready» تظهر لمزوّد لم يُتحقق من تسجيل دخوله.** `engineReady` في `frontend/src/rusebot/components/AiProviders.tsx:34` يعتبر أي `auth_state` غير `unauthenticated` جاهزًا. Antigravity ليس له أمر فحص، فيظهر Ready دائمًا، وكذلك أي مزوّد فشل فحص دخوله أو انتهت مهلته.
2. **أمر تسجيل الدخول يُعرض لمزوّد غير مثبت أصلًا.** `engines.setup` في `backend/pyworker/api/system.py:104` يرجع أمر login بغض النظر عن حالة التثبيت، ولا يوجد أمر تثبيت ولا رابط.
3. **فرع ميت في `engines.setup`.** نص «Sign in through the installed Antigravity application» لا يُنفذ أبدًا لأن كل المحركات لها أمر.
4. **«Check again» في الإعدادات لا يحدّث قائمة المحركات في الـ Composer.** كل مكوّن يحمّل نسخته: `AiProviders` و`useEngines` (`state/useChat.ts:84`) منفصلان.
5. **اختبار e2e يستعمل قيمة غير موجودة في العقد.** `e2e/rusebot_ui.spec.ts:556` يرسل `install_state: 'missing'` بينما الـ worker يرسل `not_installed`. النوع في `data/worker.ts:68` مجرد `string` فلا يكشف ذلك.
6. **«Check connection» لا يثبت أن المزوّد يعمل.** `engines.check` يرجع `generation_verified: False` دائمًا؛ الواجهة تكتب «Connected» بدون أي توليد فعلي.
7. **أكواد أخطاء خام للمستخدم**: «Not ready (timeout)».

### تجربة استخدام ضعيفة

8. الـ Composer يعرض معرّفات داخلية (`claude-code`, `mock`) بينما الإعدادات تعرض «Claude» و«ChatGPT». اسمان لنفس الشيء.
9. أسماء النماذج فيها نص للمطورين: «Claude sonnet (alias, unverified)»، «… (Codex, unverified)».
10. النماذج لا تظهر إلا بعد الضغط على «Check connection»، كقائمة نص مقطوعة عند 60، ولا يمكن اختيار نموذج منها.
11. لا يوجد مكان لتحديد المزوّد والنموذج الافتراضي؛ الاختيار مدفون في قائمة «+» في الـ Composer.
12. `NewAgentDialog` يرث المحرك والنموذج بصمت من اختيار الـ Composer ولا يسمح بتغييرهما.
13. نص تفاصيل تقني للمستخدم: «Installed; CLI reports an authenticated session. Discovery does not verify actual model execution.»
14. بطاقات `<details>` داخل grid: فتح بطاقة يحوّلها لعرض كامل فيقفز التخطيط.
15. سجل الاستخدام (`usage.summary`) موجود في الـ worker بلا أي واجهة.
16. كل فتح للإعدادات يشغّل حتى 8 عمليات CLI بلا تخزين مؤقت.

### تكرار في الكود

17. تعريف المحركات موزع على خمسة أماكن: `engine_discovery.ENGINE_SPECS`، `engine_registry.ENGINE_IDS`، أوامر `engines_setup`، جدول `engines_capabilities`، و`TITLES` في الواجهة. `adapter_supported` مجموعة مكتوبة يدويًا تساوي كل المحركات.

## ثالثًا: التصميم الجديد للمزوّدين (Providers v2)

قرار النطاق: نبقى على محركات CLI الأربعة (اشتراكات المستخدم عبر الأداة الرسمية)، بدون مفاتيح API في هذه المرحلة. إضافة مزوّدين بمفاتيح API قرار منتج يحتاج موافقة صاحب المشروع.

### عقد الـ worker (إضافات متوافقة للخلف — المفاتيح القديمة تبقى)

مصدر واحد: `backend/pyworker/runtime/providers.py` يحوي كتالوج المزوّدين (العنوان، الشركة، أوامر التثبيت والدخول، الروابط، القدرات، `provider_ids` للربط مع سجل الاستخدام). باقي الملفات تقرأ منه.

| engine_id | title | vendor | install | login |
|---|---|---|---|---|
| `claude-code` | Claude | Anthropic | `npm install -g @anthropic-ai/claude-code` | `claude auth login` |
| `codex` | ChatGPT (Codex) | OpenAI | `npm install -g @openai/codex` | `codex login` |
| `opencode` | OpenCode | OpenCode | `npm install -g opencode-ai` | `opencode auth login` |
| `antigravity` | Gemini (Antigravity) | Google | لا أمر؛ رابط `https://antigravity.google/download` | `agy acp --login` |

- **`engines.status`** `{force?: bool}` → لكل محرك تضاف: `state`, `title`, `vendor`, `checked_at`. نتيجة الفحص تُخزَّن 30 ثانية على كائن الـ context (ليس على مستوى الموديول)، و`force: true` يتجاوزها.
  `state`: `not_installed` | `error` (install غير معروف) | `ready` (مثبت + authenticated) | `needs_login` (مثبت + unauthenticated) | `unverified` (مثبت + auth غير معروف).
- **`engines.setup`** `{engine_id}` → تضاف: `state`, `install: {command: string[]|null, url: string|null}`, `login: {command: string[]|null}`, `docs_url`. `instructions` تتبع الحالة.
- **`engines.models`** → `name` نظيف («Claude Sonnet»، بدون لاحقات «unverified»)؛ الحالة تبقى في `status`.
- **`engines.test`** `{engine_id, model_id?}` (جديد) → توليد فعلي واحد بنص ثابت داخل الـ worker (لا يقبل prompt من العميل، انسجامًا مع منع `engines.tasks`). يرجع `{engine_id, model_id, ok, duration_ms, reply_preview, error_code, error_message}`. يستهلك من حصة المستخدم، فلا يُستدعى إلا بضغطة صريحة.
- **`engines.open_setup`** `{engine_id, step: "install"|"login"}` (جديد) → يفتح نافذة طرفية ظاهرة بالأمر الرسمي الثابت من الكتالوج. يرجع `{launched, reason}`. معطّل في `RUNTIME_MODE=mock` وعلى غير Windows.
- **`usage.summary`** → يضاف `by_engine` (مفتاحه `engine_id`، وغير المعروف `other`).
- **`engines.capabilities`** → نفس المخرجات، لكن من الكتالوج.

### الواجهة

- **مخزن مشترك** `rusebot/state/useProviders.ts` (`useSyncExternalStore`): الحالات، القدرات، النماذج لكل محرك (cache)، الاختيار الحالي، النموذج الافتراضي لكل محرك. `useEngines()` يبقى كواجهة رفيعة فوقه. أي تحديث في الإعدادات ينعكس في الـ Composer فورًا.
- **صفحة AI providers**: رأس + «Refresh» مع وقت آخر فحص؛ شريط «Default for new chats» (مزوّد + نموذج)؛ قائمة رأسية من الصفوف مرتبة حسب الحالة. كل صف: الشعار، الاسم، الشركة والإصدار، شارة حالة دقيقة بخمس حالات، وزر أساسي حسب الحالة (Install / Sign in / Test). عند الفتح: خطوات الإعداد المرقمة مع نسخ الأمر و«Open terminal» ورابط التوثيق؛ للجاهز: النماذج قابلة للاختيار كافتراضي، نتيجة «Send test message» (زمن + معاينة الرد)، أرقام الاستخدام، وتفاصيل تقنية مطوية.
- **Composer**: أسماء ودّية بدل المعرّفات، تعطيل غير الجاهز مع السبب، وعنصر «Manage providers…» يفتح الإعدادات على صفحة AI.
- **NewAgentDialog**: اختيار المحرك والنموذج صراحة.
- رسائل أخطاء مفهومة بدل الأكواد الخام.
- ترتيب الاختيار الافتراضي يبقى: المخزَّن ← `mock` (يظهر فقط في وضع الاختبار) ← أول جاهز. تقديم `mock` مقصود حتى لا تستدعي اختبارات e2e نماذج حقيقية.
